# BhashaBot — Complete API Connection & Production Setup Guide

A complete, step-by-step manual to connect all external APIs (**Groq LLM / OpenAI**, **Facebook Messenger**, **Telegram Bot**, and **Turso SQLite**) to make **BhashaBot** 100% production-live.

---

## Architecture & Data Flow

```
[Customer on Facebook Messenger]
            │
            ▼ (HTTPS Webhook Event)
[Next.js Webhook: /api/messenger]
            │
            ├──► 1. HMAC Signature Verification (FB_APP_SECRET)
            ├──► 2. Knowledge Grounding (lib/knowledge.ts - Catalog & Policies)
            ├──► 3. AI NLP Inference (Groq Llama 3.3 / OpenAI)
            │      ├─ Multilingual Detection (Bengali, Banglish, Hindi, etc.)
            │      ├─ Sentiment Spectrum (Happy, Neutral, Confused, Angry, Urgent)
            │      ├─ Lead Entity Extraction (Name, Phone, Email, Location)
            │      └─ Intent Classification
            │
            ├──► 4. Database Logging (libSQL / SQLite / Turso)
            │
            ├──► 5A. If needs_human = true ──► Push Alert to Telegram Bot
            │                                   (with Customer Name, Phone & Reason)
            │
            └──► 5B. If automated reply ────► Send Reply via Meta Graph API
                                                (in Customer's Exact Language)
```

## Stage 0: Instant Local Run (Zero Configuration)

BhashaBot works completely offline out-of-the-box using its built-in multilingual NLP rule engine and local SQLite database:

```bash
# 1. Install dependencies
npm install

# 2. Start the local server
npm run dev
```

Open **`http://localhost:3000`** in your browser:
- Click **"Reply studio"** to draft against a custom message in any language, script or workspace mode.
- Click **"Send a test message"** to push a realistic inbound conversation through the pipeline.

## Stage 1: Connect Real AI Model (Groq Llama 3.3 or OpenAI)

To enable deep language understanding, conversational nuance in native Bengali script and Romanized Banglish, and automatic lead entity extraction:

1. Visit **[Groq Console (console.groq.com/keys)](https://console.groq.com/keys)**.
2. Sign up and click **Create API Key**. Copy your key (`gsk_...`).
3. Create or open `.env.local` in the project root:
   ```env
   GROQ_API_KEY=gsk_your_groq_api_key_here
   GROQ_MODEL=llama-3.3-70b-versatile
   ```
4. *(Optional)* If you prefer OpenAI, set:
   ```env
   OPENAI_API_KEY=sk-proj-your_openai_key_here
   ```
5. Restart the server (`Ctrl + C`, then `npm run dev`).
6. **Verify**: Open **Settings -> Model**, paste the key there instead if you prefer, and press **Test connection**. Then open the **Reply studio** and draft a reply; it is now generated by the model rather than the rule engine.

---

### Find out which models your key can reach

Instead of guessing a model id, paste the key into **Settings → Model and API** and press **Scan available models**. The desk queries that provider's model list with the key you just typed — without saving it — and refills the model picker with everything the key can actually reach, minus the ids that cannot hold a conversation (embeddings, speech, moderation). A wrong key comes back as *Key rejected* right there.

| Provider | Scanned from |
|---|---|
| Groq, Cerebras, Mistral, Together, Hugging Face, OpenAI, custom | `<chat endpoint>/models` |
| Google AI Studio (Gemini) | `…/v1beta/openai/models` |
| OpenRouter | `https://openrouter.ai/api/v1/models` |
| Anthropic | `https://api.anthropic.com/v1/models` |

## Stage 2: Connect Telegram Bot for Escalation Alerts

When a customer expresses frustration, requests a refund, or demands a human agent, BhashaBot sends an instant rich alert to your private Telegram:

1. Open Telegram and message **[@BotFather](https://t.me/BotFather)**.
2. Send `/newbot`, name your bot (e.g. `BhashaBot Support`), and pick a username ending in `bot` (e.g. `bhashabot_support_bot`).
3. BotFather will provide your **API Token** (e.g. `1234567890:ABCdefGhIJKlmNoPQRsTUVwxyZ`).
4. **Important**: Open a chat with your new bot and click **Start** or send any message (e.g. *"Hello"*).
5. Find your numeric Telegram Chat ID by visiting this URL in your browser:
   ```
   https://api.telegram.org/bot<YOUR_BOT_TOKEN>/getUpdates
   ```
   *(Replace `<YOUR_BOT_TOKEN>` with your token. In the JSON output, look for `"chat":{"id":123456789}`)*.
6. Add both values to your `.env.local`:
   ```env
   TELEGRAM_BOT_TOKEN=1234567890:ABCdefGhIJKlmNoPQRsTUVwxyZ
   TELEGRAM_CHAT_ID=123456789
   ```
7. **Verify**: Open **Settings -> Channels** and click **"Send a test alert"**. Check your Telegram chat.

## Stage 3: Connect a Real Facebook Messenger Page

To automatically reply to messages on your Facebook Business Page:

### 1. Create Meta Developer App
1. Go to **[developers.facebook.com](https://developers.facebook.com)** → **My Apps** → **Create App**.
2. Select **Other** → **Business** (or Consumer). Name your app `BhashaBot`.
3. In the App Dashboard, find **Messenger** under "Add products to your app" and click **Set Up**.

### 2. Generate Page Access Token
1. In the left menu, navigate to **Messenger → Settings → Access Tokens**.
2. Click **Add or remove Pages** and select your Facebook Page.
3. Click **Generate Token**, copy the token, and add it to `.env.local`:
   ```env
   FB_PAGE_ACCESS_TOKEN=EAAG...your_page_access_token
   ```

### 3. Configure Webhook
1. Still under **Messenger → Settings**, scroll down to **Webhooks** → **Add Callback URL**:
   - **Callback URL**:
     - **For Deployed Apps**: `https://your-domain.vercel.app/api/channels/messenger`
     - **For Local Development**: Run `npx localtunnel --port 3000` (or `ngrok http 3000`) and paste `https://your-tunnel.loca.lt/api/channels/messenger`.
     - The older `/api/messenger` path still works, so an existing webhook does not have to be moved.
   - **Verify Token**: `my-verify-token` (must match `FB_VERIFY_TOKEN`).
2. Click **Verify and Save**. Meta will send a `GET` handshake to your endpoint and verify it.
3. Under **Webhook fields**, click **Manage** and subscribe to:
   - `messages`
   - `messaging_postbacks`

### 4. Enable HMAC SHA-256 Signature Security
1. Go to **App Settings → Basic** in the Meta Developer console.
2. Click **Show** next to **App Secret** and copy it.
3. Add to `.env.local`:
   ```env
   FB_APP_SECRET=your_app_secret_here
   FB_VERIFY_TOKEN=my-verify-token
   ```

## Stage 3b: The Other Platforms (Instagram, WhatsApp, Discord, Slack, anything)

Every platform is switched on individually in **Settings → Platforms**. Each card there shows its own webhook URL, its credential fields, its setup steps and a link to the official docs. A platform left switched off refuses inbound posts with a `403`.

### Instagram DM — `/api/channels/instagram`
1. Switch the Instagram account to **Professional** and link it to your Facebook Page.
2. In the same Meta app, add **Instagram** and grant `instagram_manage_messages`.
3. Point the Instagram webhook at `https://your-domain/api/channels/instagram` using the **same verify token** as Messenger.
4. Leave the Instagram token blank to reuse the Page access token, or paste a dedicated one.

### WhatsApp Cloud API — `/api/channels/whatsapp`
Covered in full in **Stage 4** below.

### Telegram — `/api/channels/telegram`
Beyond alerts, the same bot can answer for you. Register the webhook once:

```bash
curl "https://api.telegram.org/bot<token>/setWebhook?url=https://your-domain/api/channels/telegram"
```

### Discord — `/api/channels/discord`
1. Create an application at [discord.com/developers](https://discord.com/developers), add a bot, copy the **bot token**.
2. Copy the **application public key** from *General Information*.
3. Set the **Interactions Endpoint URL** to `https://your-domain/api/channels/discord`. Discord immediately sends a signed ping; the desk verifies it with Ed25519 and answers, which is what makes the URL save.
4. Add a slash command with a `text` (or `message`) option — that option is what gets answered.

```env
DISCORD_BOT_TOKEN=...
DISCORD_PUBLIC_KEY=...
```

### Slack — `/api/channels/slack`
1. Create an app at [api.slack.com/apps](https://api.slack.com/apps), add the `chat:write` and `im:history` scopes.
2. Install it to the workspace, copy the **bot token** and the **signing secret**.
3. Enable **Event Subscriptions** with `https://your-domain/api/channels/slack` and subscribe to `message.im`.

```env
SLACK_BOT_TOKEN=xoxb-...
SLACK_SIGNING_SECRET=...
```

### Anything else — `/api/channels/web`
A site chat widget, Zapier, n8n, Viber, LINE, a cron job, your own script. POST JSON and the drafted reply comes straight back:

```bash
curl -X POST https://your-domain/api/channels/web \
  -H "Content-Type: application/json" \
  -H "x-bhasha-secret: your-secret" \
  -d '{"text":"Do you deliver to Sylhet?","senderId":"visitor-42"}'
```

```json
{
  "ok": true,
  "results": [
    {
      "reply": "Yes, Sylhet is covered...",
      "sentiment": "neutral",
      "intent": "delivery_inquiry",
      "mood": "warm",
      "needsHuman": false,
      "detectedLanguage": "English"
    }
  ]
}
```

Set `WEBHOOK_SECRET` (or the field in Settings) to require the `x-bhasha-secret` header; leave it blank to accept unauthenticated posts.

## Stage 3c: Moods and Their Pages

Ten moods ship with the desk, and each one has its own page at `/moods/<mood>`: `warm`, `professional`, `concise`, `empathetic`, `playful`, `persuasive`, `apologetic`, `assertive`, `romantic`, `flirty`.

1. Open **`/moods`** (or the *Moods* item in the nav, or `⌘K → Moods`).
2. Pick a mood to see what it is built for, worked examples in English and Bangla, and the exact directive the model receives.
3. Paste a real message into **Try this mood** — it drafts with that mood only and never touches your saved settings.
4. Press **Use this mood** to make it the desk's active mood.

**Romantic** and **flirty** are written for a *Personal* workspace. Both carry a standing guard in the prompt: never explicit, never about someone's body, and the tone is dropped the moment the other side is not reciprocating. In a Business, Official or Support workspace the desk automatically holds them to a friendly, professional register instead.

## Stage 4: Connect WhatsApp Cloud API

To automatically reply to messages on your WhatsApp Business number:

### 1. Create Meta Developer App
1. Go to **[developers.facebook.com](https://developers.facebook.com)** → **My Apps** → **Create App**.
2. Select **Other** → **Business** (or Consumer). In the App Dashboard, find **WhatsApp** under "Add products to your app" and click **Set Up**.
3. Under **WhatsApp → API Setup**, you will be given a temporary access token and a test Phone Number ID.

### 2. Configure Webhook
1. In the left menu, navigate to **WhatsApp → Configuration**.
2. Click **Edit** under Webhook:
   - **Callback URL**: `https://your-domain.vercel.app/api/channels/whatsapp` (or your local tunnel).
   - **Verify Token**: `my-verify-token` (must match `FB_VERIFY_TOKEN`).
3. Click **Verify and Save**. Then, click **Manage** on the Webhook fields and subscribe to `messages`.

### 3. Add Credentials to Environment
1. Copy the **Access Token** and **Phone Number ID** from the API Setup page.
2. Add them to your `.env.local` (or enter them directly in **Settings -> Channels** in the UI):
   ```env
   WHATSAPP_ACCESS_TOKEN=your_whatsapp_access_token_here
   WHATSAPP_PHONE_NUMBER_ID=1234567890
   ```
3. Restart the server and ensure **WhatsApp** is enabled in the Settings.

## Stage 5: Persistent Cloud Database (Turso — Free SQLite)

Local SQLite (`local.db`) is ideal for development. On serverless platforms like Vercel, the filesystem resets between requests, so connect a free **Turso** cloud database:

1. Install the Turso CLI:
   ```bash
   # On macOS/Linux:
   curl -sSfL https://get.tur.so/install.sh | bash

   # On Windows (PowerShell):
   irm https://get.tur.so/install.ps1 | iex
   ```
2. Authenticate and create a database:
   ```bash
   turso auth signup
   turso db create bhashabot
   ```
3. Retrieve database URL and Auth Token:
   ```bash
   turso db show bhashabot --url
   # Output: libsql://bhashabot-username.turso.io

   turso db tokens create bhashabot
   # Output: eyJhbGciOi...
   ```
4. Add to `.env.local` and your Vercel Environment Variables:
   ```env
   TURSO_DATABASE_URL=libsql://bhashabot-username.turso.io
   TURSO_AUTH_TOKEN=eyJhbGciOi...
   ```

## Stage 6: Deploy to Production (Vercel)

1. Push your repository to GitHub:
   ```bash
   git push origin main
   ```
2. Go to **[Vercel (vercel.com)](https://vercel.com)** → **Add New Project** → Import your GitHub repository.
3. Under **Environment Variables**, add:
   - `GROQ_API_KEY` & `GROQ_MODEL`
   - `TELEGRAM_BOT_TOKEN` & `TELEGRAM_CHAT_ID`
   - `FB_PAGE_ACCESS_TOKEN`, `FB_VERIFY_TOKEN`, `FB_APP_SECRET`
   - `TURSO_DATABASE_URL` & `TURSO_AUTH_TOKEN`
4. Click **Deploy**. Vercel will build and assign an HTTPS domain (e.g., `https://bhashabot.vercel.app`).
5. Update your Meta Webhook URL to `https://bhashabot.vercel.app/api/messenger`.

## Training the private persona mood

1. Put the chat exports in `demo-messages/` — one JSON per thread, in Meta's export shape:

   ```json
   {
     "participants": ["Pritom Biswas", "Nayan Biswas"],
     "threadName": "Nayan Biswas_36",
     "messages": [
       { "senderName": "Nayan Biswas", "text": "kothay tui", "timestamp": 1727347033826, "type": "text" }
     ]
   }
   ```

2. Label whoever matters in `lib/relationships.ts` (`ROSTER`). Anyone not listed is treated as a friend.
   The same roster drives the relationship badge in the live feed.

3. Train:

   ```bash
   npm run train:persona
   ```

   It prints what it read and what it kept, and writes `lib/persona/pritam-style.json`. Re-run it any time
   you add threads; the app reads the file at runtime, so no rebuild is needed in production either.

4. Set the password before deploying:

   ```bash
   # .env.local
   MOOD_PASSWORD=something-only-you-know
   ```

5. In the app: Settings → Voice → pick **Pritam**, enter the password, then pick a sub-mood
   (friendly, flirty, romantic, angry, sad, caring). Set the workspace to **Personal** as well — in a
   business, official or support workspace the intimate sub-moods are deliberately held to a friendly,
   professional register.

Neither `demo-messages/` nor the trained JSON is committed. Both are in `.gitignore`.
